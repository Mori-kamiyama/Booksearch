# Webプログラミング アクティブラーナー企画書

## 用件

授業で学べない高度な内容をもとに特別評価される取り組み。
＋v100プロジェクトに活用できるよう何らかのAI、シミュレーションが入っていること。

## 動機

本検索するのムズい！！本どこにあるかわかんない！
 → 本検索エンジンがあったらええやん！

本の検索を中心として選書とか、自分の家の本棚をデジタル化して検索ができる検索ツールと
自分の読書内容とか本棚内容をもとにした、選書ツールを一体化し、

大量にある本の中からおすすめし、すぐに手に取ってもらえる。
果樹から身をとるようにいい本を手に取れるサービスを作ろうと思い。
「ホンノキ」を思いついた。


## 内容

本棚検索engine 「ホンノキ」
本棚の画像をWebカメラでスキャンし、OCRと書籍照合によって目的の本がどこにあるかを特定するWebアプリ。
利用者は検索した本がありそうな棚を案内され、その棚を追加でスキャンすることで、棚のどのあたりにあるかを視覚的に確認できる。
本を借りる機械の近くに設置し、学校内で本を探す時間を短縮することを目指す。

## 詳しい技術スタック

### フロントエンド

- Vite
- React
- TypeScript
- Tailwind CSS
- Webカメラ入力
  - `getUserMedia` を使って本棚画像を取得する
- 棚位置の可視化
  - まずは2Dの案内表示を行い、必要に応じてWeb ARへ拡張する

### インフラ

- AWS
  - フロントエンド配信: S3 + CloudFront
  - 画像保存: S3
  - Webバックエンド: API Gateway + Lambda
  - 非同期処理: SQS + Lambda
  - OCR: Amazon Textract
  - データベース: RDS PostgreSQL

### Webのバックエンド

- Goで開発する

- 機能
  - 書籍検索API
  - 本棚スキャン受付API
  - 棚位置表示API

- OCRと照合の流れ
  1. 利用者が本を検索する
  2. システムが候補となる棚・エリアを信頼度付きで複数提示する
  3. 利用者がその棚をスキャンする
  4. 非同期ワーカーがOCRと書籍照合を行う
  5. 一致した候補から棚内の位置を返す
  6. スキャン結果に応じて棚候補の信頼度を更新する

- 本のAPIとのマッチング
  - 楽天Book API
  - Google books API

- 本の検索
  - 完全一致検索
  - 前方一致検索
  - ファジー検索
  - PostgreSQL の全文検索や類似検索の活用を検討する
  - 一致した書籍に対して複数の棚候補を提示し、上位候補から探索する

- 構成方針
  - 検索APIや状態確認APIなどの同期処理は API Gateway + Lambda で受ける
  - OCRや書籍照合などの時間がかかる処理は SQS + Lambda で非同期に実行する
  - 初期段階では常時起動サーバを置かず、Lambda-only 構成でコストを抑える

#### 中にあるべきデータ構造

- 書籍データ
  - 学校内に存在する書籍データを保存する
  - OCR時の照合先として使う

- 本棚データ
  - 本棚ID
  - 棚番号
  - 段番号
  - エリアデータ

- 棚内の配置データ
  - 書籍ごとに複数の棚候補を持つ
  - 各棚候補に信頼度を持たせる
  - 書籍と棚位置の対応
  - 最終確認日時
  - 確定データと推定データの区別
  - 古い棚位置データは時間経過によって信頼度を下げる
  - OCR一致度や再スキャン結果によって信頼度を更新する

- スキャンデータ
  - アップロード画像
  - OCR結果
  - 候補書籍
  - 信頼度
  - 処理状態

## このアイデアの技術的難しさ

- 私がAWSが何もわからない。 AWS初心者
- データが古くなる中でどのように理想的なデジタルツインを構築するか
- AWSの基本機能をすべて使う網羅性
- 本の書影データと本を一致させる難しさ　事前実験だと80%くらいしか上手くいかない


## スケジュール

2週 ~ 3週

1. MVPとしてまず、本棚を切り取り台形補正しOCRを行い、書籍APIと組み合わる。それをもとにして本を検索するプログラムを作成する。

4 ~ 6週

2. 取り出した背表紙と正しい書籍名とISBNを取得する組み合わせプログラムを作成する。

7週

3. OCRプログラムをAWSに移管しOCR APIを作成する。

8 ~ 9週

4. PostgreSQLにデータを入力できるようにし、PostgreSQLでの一致検索を実装する

10 ~ 11週

5. 信用度の定期Updateを作成する。

12 ~ 13週

6. きれいなフロントエンドを作成する

7. 全部繋げる
