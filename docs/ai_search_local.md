# ローカルAI検索の初版

> 状態: 独自AI検索はユーザー判断で取り下げ。画面・入口・開発プロキシを撤去し、ローカルAIサーバーも停止。以下は試作時の記録で、現在のアプリ仕様ではない。検索ロジックは検証資料として保持し、ChatGPT接続は未実装。

通常検索にベクトル検索を追加しない判断を維持し、目的や条件を文章で入力する独立したAI検索を追加した。開発時だけ `/ai-search` を表示し、ホームからリンクする。公開API・本番デプロイは変更していない。

## 処理

`scripts/ai_search.py` は既存の閉じた生成済みSQLiteカタログを読み取り、Bedrock Nova Pro（APAC inference profile）のConverse/tool useで最大6応答まで検索する。

1. search: 日本語の短いキーワードを最大3つ指定。各クエリはAND、クエリ間はOR。書名・著者・既存別名・確認済み内容紹介を検索し、最大16冊のプレビューを返す。
2. inspect: 検索済み候補を最大8冊まとめて確認。内容紹介は最大3,000文字。
3. finish: 確認済みの本を最大5冊（指示上は適合性の高い1〜3冊を優先）選び、内容紹介の根拠IDを指定する。IDから元の文章を取得して表示する。

検索結果が弱ければ再検索できる。AIが作った書名・引用・URLは表示しない。検索・確認済みIDと根拠IDを実行側で検証し、不正な操作にはツールエラーを返す。書誌データ中の指示には従わない旨をモデルへ指示しているが、目的適合性自体の誤判定まで防げる保証はない。

最初の試験でAIが指定のないmin_pages=1を足して、ページ数不明の本を落としていた。対策としてモデルにはページ数条件を操作させない。フォームの上限と、文章の「300ページ以下・以内・未満・まで」「100ページ以上・超」（頁も可、全角数字可）を実行側で抽出・交差し、全検索に適用する。曖昧な「薄め」「300ページくらい」などは数値条件へ自動変換しない。確実な上限はフォームで入力する。

引用をモデルに書き写させる方式では空白などの改変と長さ超過が生じ、訂正ループが起きた。現在は元の紹介文を分割してIDを振り、IDだけ選ぶ。販売部数・ベストセラーなど明らかな宣伝文句を根拠候補から除外した。語句の選び方や対象読者の判定は引き続き評価が必要。

## 実行

```sh
uv run --no-project --with boto3 python scripts/ai_search.py \
  --db outputs/discovery-language/library.db --serve
```

127.0.0.1:18091だけで待ち受ける。Viteが `/ai-api` をここへ転送する。AWS資格情報はPython側で使用し、ブラウザに渡さない。同時実行1、モデルの自動リトライなし、各呼び出しread timeout 12秒、ラウンド開始・終了時に全体45秒を確認する。最後の呼び出し分だけ超過し得るためUIは60秒で打ち切る。画面を離れるとブラウザの待機は中止するが、進行中のモデル呼び出しをサーバー側でキャンセルする機能は未実装。

実測では連続した検証でBedrockのThrottlingExceptionが出た。サーバーは429と再試行メッセージを返す。認証・本番の利用制限・課金監視・複数ユーザー運用は未実装なので、開発用の公開範囲を拡大しない。検索文と候補の書誌・内容紹介をBedrockへ送る。全カタログの一括送信やベクトル生成はしない。

## 確認

- AI検索ロジック13テスト、既存ベクトル比較7テスト成功。条件を緩めない、ページ数不明の扱い、未確認ID・架空引用の拒否、モデルの条件創作の拒否、回数上限、数値抽出を検証。
- 開発サーバーでPlaywright3件成功。送信前のモデル呼び出しなし、結果リンク・根拠、失敗後の再試行、未完了と該当なしの区別、320pxで横スクロールなし。
- フロントエンドproduction build成功（既存OpenCVチャンク警告あり）。AI検索ルートと入口はDEV限定。
- 実モデルで英語学習者向けの「日本語を活用して学ぶ英文法」を取得。根拠は日本語を振り返って英語を学び直す旨の紹介文。
- 「Pythonでデータ分析を学びたい。300ページ以下」を実ブラウザ390pxで確認。202ページの「Python2年生データ分析のしくみ」と175ページの「データの前処理」を返し、紹介文の原文を表示。後者の紹介文にはPython基礎の付録も記載。
- APIの成功2例は約2.1〜2.7秒。全体精度や速度の保証ではない。現段階はローカル試用版。

次の判断は、ユーザーの実際の文章で、候補の適合性・取りこぼし・根拠の有用性を確認してから行う。現在は内容紹介のない本を最終候補にできず、最大16件の検索候補から選ぶため、全件を網羅した結果ではない。

該当なしの実モデル試験も確認。架空の書名で検索0件を経て、空の候補を返した（約3.7秒）。モデルがツールを使わず文章だけ返す場合は、上限内でツール使用を促し、文章を検索結果として表示しない。

## 対話型への変更

`/ai-search` を会話形式に変更した。以前の目的と候補を引き継ぎ、追加の希望を送信できる。履歴はタブのsessionStorageに保持し、詳細画面から戻る・再読み込みで復元する。「新しい会話」で履歴・条件を解除する。最大8往復で新しい会話へ誘導する。失敗した送信は履歴へ追加せず、入力と以前の候補を保持する。

APIは最大8件の履歴（質問・返信・候補ID）を受け取り、候補IDから蔵書の書名とページ数を読み直す。モデルに古い検索結果をそのまま確定させず、そのターンでも検索・確認を必須とする。`clarify` ツールで、目的が不明な場合や「もっと薄い」の上限確認を1問と最大3選択肢で返せる。質問には自由入力でも回答可能。

数値条件は現在の画面状態を正とする。最新の発言で「500ページ以下」に変えれば前の200ページから変更でき、画面の解除ボタンか「ページ数の制限はなし」で外せる。過去の文章を毎回解析して解除済み条件を復活させない。明示したページ数に回答済みの場合、同じページ数の確認質問を実行側で拒否する。目的・分野は会話の本文で確認できるが、個別のテーマ条件チップにはまだしていない。

実モデルで、ページ数を検索語に含めたり、0件なのに語を増やす挙動があった。ページ数表現は検索語から除去し、3語以上のAND検索が0件なら末尾の語を減らして候補を広げる（最低2語）。数値条件は維持し、最終的な適合性は内容紹介の確認で判断する。元の検索と再検索は履歴に記録する。

検証: ロジック19件・ブラウザ4件、production build成功。実モデルで「Pythonでデータ分析」→「もっと薄い」ではページ数確認を返した。その会話への「200ページ以下」の回答で、Pythonの目的を引き継いだ検索から175ページの「データの前処理」を取得した（最終ターン約2秒）。390pxで会話・候補カード・入力欄、320pxで横スクロールなしを確認。検証中のAWSタイムアウトでエラー処理が例外になっていたため修正し、非JSON応答時も再試行できるメッセージにした。

制約: 条件の意味的な引き継ぎや候補の適合性はモデル判断なので、全ケースを保証しない。サーバー側の会話保存・認証・本番公開は行っていない。リセットや画面移動はブラウザの待機を中止するが、進行中のAWS処理は既存の時間・回数制限内で継続する。

## GenUIのローカル試作

用途の確認は選択カード、検索結果は書籍カード、比較は取得済み情報の表として表示する。モデルは検証済みの表示種別を選び、任意HTMLやコードは生成しない。自由入力は常に使え、候補と任意の追加質問を同時に表示できる。ページ数入力は折りたたみ、明示条件としてのみ適用する。「簡単め」はページ上限へ変換せず、「ページ数は気にしない」で上限を解除できる。比較は最大3冊で追加のモデル呼び出しなし。

Nova Liteは目的の決めつけと再検索の繰り返しが残ったため、ローカル既定を `apac.amazon.nova-pro-v1:0` に変更。東京のBedrockからAPACクロスリージョン推論を使う。Nova Liteとは利用料金が異なる。本番設定は変更していない。必要なら `--model` で明示する。

実モデルの少数試験: 「英語の本が読みたい」は学習・英語で読む・デザインの3用途を確認（約1.6秒）。ページ数質問への「簡単め」は数値を再質問せず候補へ進んだ（約4.5秒）。デザインへの変更も検索に反映（約5.3秒）したが、日本語訳のデザイン解説書を返し、英語の紙面が必要かは未解決だった。主題なしの「初級」検索と翻訳書の言語の混同を避ける指示を追加したが、これで適合性が保証されたわけではない。難易度・言語・用途の評価は継続する。

検証: Python22件・Playwright5件成功、production build成功。自由入力による方向転換、選択カード、比較時に通信しないこと、320pxで横スクロールなしを確認。段階ごとの目的・好みを独立した構造状態として保持する実装はまだなく、会話履歴と目的表示を利用する。
