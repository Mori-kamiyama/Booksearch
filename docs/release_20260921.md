## データと推薦

反映前の本番API同梱DBを読み取り、手元のDBとSHA-256一致を確認した。4,202冊のコピーに対して以下を実行した。

```sh
uv run --no-project python scripts/build_bm25_recommendations.py \
  --db /tmp/booksearch-related-preview.db --top-k 6 --conservative
```

4,102冊に23,219件を生成。100冊は候補不足のため空のままとする。自己参照・同一ISBN・同名同著者のコピー・候補間重複を除外し、理由が存在することを全件確認。元DBのすべての既存テーブルについて双方向EXCEPTで不変を確認し、SQLite integrity_checkも成功。SQLite backupでAPI/lookupの同梱DBへ同じsnapshotを反映した。

通常BM25では「シベリアのバイオリン」から「バイオプラ」「オリンピック」への文字片一致があり、そのまま配信する品質には足りなかった。初期配信では同一正規化著者、分類先頭3文字、共通カテゴリのいずれかを必須にした。20冊を抜き出した確認でも、分類による広い候補は残る。書誌情報に基づく初期版であり、読者による関連性・多様性の評価は継続課題。

## 実測で残った遅延

おすすめはAPIを事前生成済みにし、新規Chromium contextを20回作成して、最初の本のボタンが見えるまでを計測した。中央値598ms、p95 2,572msで、初回1秒の目標は未達。これはキャッシュのある再訪の109msとは別の測定。全表紙画像の読み込み完了も条件にしていない。20回計測時は読み取りsmokeも並行実行していた。続けて10回直列で調べると、おすすめAPIは129〜303ms、画面全体は553〜1,803msであり、初期document/画面起動側の改善余地がある。

空画像解析ではYOLOのINIT_REPORTに約10秒の初期化timeoutが2回出た後、正常処理に進んだ。同一taskの重複配送はlease保護で再試行され、task消失・DLQ移行はなかった。初期化を含む呼び出しに約53.5秒・106.5秒の記録があり、cold startの短縮は未解決。重いライブラリのimportが起因する可能性はあるが、今回の検証だけでは個別の内訳を確定していない。
