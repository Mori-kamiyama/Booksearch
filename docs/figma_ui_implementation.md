# Figma UI 実装メモ

対象: Figma `BookSearch`（fileKey: `DIviU7JjjSD2eydcYW2LLH`）の検索フロー・索引・メニュー。

- モバイル検索 `5:43`、検索結果 `5:73`、詳細 `6:127`（402×874）
- モバイル索引 `9:364`（Map）/ `9:710`（リスト）（402×874）
- PC検索 `10:856`、検索結果 `10:921`、詳細 `10:986`（1280×832）

## 実装したこと

- `/` → `/search?q=...` → `/books/:id?q=...` の検索フローを分離
- 検索中は結果カードと同じ寸法のスケルトンを表示
- APIの応答が速い場合も状態が判別できるよう、スケルトンを最低350ms表示
- モバイルは2列、PCは5列の結果グリッドを実装
- 詳細画面に内容要約、棚マップ、推薦書籍を実装
- Figma内の書影8点をローカルPNGとして保存し、外部URLの期限に依存しない構成に変更
- スキャン `6:239`、録画中 `8:262`、スキャン結果 `9:282` を既存処理へ接続
- スキャン画面では中央ボタンを録画開始・終了、右下ボタンを単発画像／動画の選択に割り当て
- スキャン結果は実際のジョブ結果を棚単位にまとめ、Figmaと同じ3列書影で表示
- 管理画面には従来の最大幅と下部ナビゲーションを維持
- ハンバーガーメニューを実装（`SiteHeader` → 右側ドロワー）。さがす・索引・スキャンに加え、下部に管理系リンク（図書室マップ・棚の管理・タグ配置）。ヘッダーの `backdrop-blur` が `fixed` の基準を変えるため `createPortal` で body 直下に描画
- 索引ページ `/index` を新設（`IndexPage.tsx`）。Map/リストの丸形トグル（`9:364`/`9:710`）
  - Map: フロアマップ（実レイアウトの base 4台=縦バー+脚、side 4台=横バー、選択棚を `#087f5b`）→ 選択ユニットのセルグリッド（13×7、空白領域は非表示）→「この棚の本」3列グリッド。セルの shelf_id は DB と同じ物理座標で組む（`ShelfMapHighlight` と同方式。`ShelfUnitGrid` の表示座標方式だと mirrored ユニットでズレる）
  - リスト: shelf-candidates から重複排除した全書籍を五十音行（あ〜わ・英数・その他）でグループ化、緑の行見出し+3列グリッド。漢字始まりの読みは取得不能なため「その他」に分類
  - データ源は `GET /api/shelf-candidates`（一覧取得APIが無いため）。書影はローカルPNGフォールバック、無ければ `#d9d9d9` プレースホルダ

## 照合結果

検索画面はブラウザ上の座標をFigmaメタデータと比較した。

- モバイル: 見出し `(28, 244, 346×29)`、検索欄 `(28, 305, 346×48)`、スキャンCTA `(103, 740, 196×71)`
- PC: 見出し `(418, 279, 444×29)`、検索欄 `(418, 362, 444×54)`、書影列 `y=596`、スキャンCTA `(1158, 675, 90×90)`
- スキャン: 戻る `(44, 40, 40×40)`、状態表示 `(51, 591, 300×63)`、録画ボタン `(145, 694, 100×100)`
- スキャン結果: 終了見出し `y=117`、案内文 `y=193`、区切り線 `y=320`、最初の棚見出し `y=353`

ブラウザの整数ピクセル丸めを含め、Figmaとの差は各軸で最大1px。

## 仮説

Figmaには検索中の独立フレームがないため、結果一覧の骨格を保つスケルトンを採用した。これなら検索開始から結果確定まで画面構造が動かず、ユーザーが次に何が表示されるか把握しやすい。
