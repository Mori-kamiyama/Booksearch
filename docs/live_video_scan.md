# 動画スキャンの修正メモ

## 確認した事実

- フロントは動画の拡張子と MIME type を保ったまま `POST /api/scan/init` → S3 PUT → `POST /api/scan/start` を実行している。
- AWS の `yolo_worker` は入力キーを常に `cv2.imread()` に渡していたため、`.mp4` やスマホの `.mov` は `unreadable image` になっていた。
- ローカル Go バックエンドには動画を `--video` で処理する分岐が既にあるが、AWS ワーカーには同等の分岐がなかった。

## ブラウザ側AprilTag検知の改善

- ブラウザ検知の入力を最大1280pxにし、小さいタグを拾いやすくした（サーバー送信用フレームは従来どおり最大960px）。
- 検知間隔を450msから650msにして、スマホのWASM処理が詰まりにくくした。
- OpenCV.jsのRGBA/RGB入力差、AprilTag向けコーナー補正、WASM初期化失敗後の再試行に対応した。
- 安定判定を同じタグ2フレームに短縮し、検知から棚表示までの待ち時間を減らした。
- OpenCV.jsの`aruco_RefineParameters`はC++のデフォルト引数を引き継がず、`(10, 3, true)`の3引数が必要だった。0引数で生成していたため、ブラウザ検知が常にフォールバックしていた。
- `data/apriltag_library_map.json` をフロントに同梱し、APIが停止していてもブラウザのtag ID・棚ユニット表示までは継続できるようにした。APIは利用可能なときだけ詳細判定を補完する。

## ローカル実行時の注意

`frontend/.env.development.local` はAPIを `http://127.0.0.1:8090` に向けている。ここが起動していない場合、サーバー検知側はCORSエラーに見えるが、実際には接続拒否（ステータスなし）である。バックエンドを8090で起動するか、利用ポートに合わせて環境変数を変更する。

## スマホUIとWASM互換性

- トップ画面は`html`・`body`を含めて縦横のオーバースクロールを止め、スキャンボタンをsafe areaより上の固定位置に表示する。
- おすすめ本はAPIが空または失敗でも同梱データを先に表示する。スマホでは表紙枠とタイトル領域を分離し、長いタイトルが表紙へ重ならない寸法にする。
- 一部スマホのOpenCV.jsではAprilTag専用コーナー補正やWASMオブジェクト破棄が`null function`を呼ぶ。コーナー補正は`SUBPIX`を使い、破棄失敗は検出結果をフォールバック扱いにしない。

## 連続棚トラッキング

- 録画開始ボタンを押した後にブラウザ検知・サーバーfallback・候補フレーム収集を並列開始し、カメラを移動しても検出済みタグをセッション中保持する。
- UIでは現在映っているタグを「追跡中」、画面外へ出たタグを「認識済み」としてチップ表示する。既読棚への再移動は再追跡するが、新規棚としては重複記録しない。

## 修正方針

AWS ワーカーで動画を OpenCV の `VideoCapture` から 0.5 秒間隔（既定、環境変数で変更可）に JPEG フレームへ変換し、既存の `process_frame()` に流す。1ジョブあたりのフレーム数は既定 120 枚で上限を設け、処理後は `/tmp` の動画・抽出フレームを削除する。

## 未確認・次の検証

- Lambda コンテナ内の OpenCV が、端末由来の MP4 / QuickTime MOV（特に HEVC）を実際にデコードできるかは、Docker イメージ上でスマホ動画を使った実機検証が必要。
- その検証で MOV/HEVC が読めない場合は、Lambda イメージに ffmpeg を追加するか、アップロード前にブラウザで互換形式へ変換する。
