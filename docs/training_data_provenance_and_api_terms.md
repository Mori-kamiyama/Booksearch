# 背表紙OCR学習データの作成方針とAPI規約

確認日: 2026-09-23

> 法律相談ではなく、公開されている利用規約を基にしたプロジェクト上の安全側の判断。

## 結論

Gemini APIのOCR出力を候補ラベルとして使い、書籍検索や人手確認を経て独自OCR/VLMを学習する方法は採用しない。

現行のGemini API Additional Termsは、Gemini APIやGoogle AI Studioと競合するモデルの開発へのサービス利用を禁止している。Vertex AIの生成AIサービスにも、生成出力を競合モデル開発へ使わないという同種の制限がある。

書籍検索や人手確認を挟めば最終ラベルの正確性と出所は改善するが、Geminiをモデル開発工程に利用したこと自体が規約上問題にならないとは断定できない。Googleから書面による許可を得ない限り、安全な方法として扱わない。

OpenAIの現行Services Agreementにも、許可された例外を除き、出力をOpenAIと競合するAIモデルの開発へ使わないという制限がある。OpenRouter経由でもモデル提供者の規約が適用されるため、回避策にはならない。

## 採用するデータ作成経路

1. 自分たちが撮影・利用許諾を得た棚画像を使う
2. Bookfinder系OBBで背表紙Cropを作る
3. Apache-2.0のローカルモデルで候補文字列を作る
   - PP-OCRv6
   - PaddleOCR-VL
   - Qwen3.5/Qwen3-VLの公開ウェイト
4. 利用条件を確認した書誌DBから書名候補を検索する
5. 人が画像と候補を照合し、正しい全文転記を確定する
6. 確定ラベルと出典・確認者・確認日時を保存する

Gemini等の商用生成APIは、学習データに入らない本番フォールバック、または独立した評価用途に限定する。評価結果を教師ラベルへ還流させる場合も、規約上のモデル開発利用と解釈される余地があるため避ける。

## 推奨する来歴フィールド

各アノテーションに最低限、次を持たせる。

```json
{
  "image_id": "...",
  "transcription": "...",
  "title": "...",
  "label_source": "human_verified_catalog",
  "candidate_generator": "PaddleOCR-VL-0.9B",
  "catalog_source": "...",
  "catalog_record_id": "...",
  "reviewer": "...",
  "reviewed_at": "...",
  "uncertain": false
}
```

書名などの短い事実情報と、本の表紙・装丁画像の権利は別に扱う。外部サイトの表紙画像を学習データへ転載せず、自分たちの棚画像を使う。書誌APIやデータベースについても、保存・再配布・商用利用の条件を個別に確認する。

## 書面確認が取れる場合

Geminiなどを使いたい場合は、用途を具体的に記載して提供者へ確認する。

- 背表紙画像のOCRだけに利用する
- 出力は書誌DBと人手で検証する
- 0.9B〜2Bのタスク特化OCRモデルを学習する
- モデルを自社サービスで利用するか、公開・販売するか
- API出力そのものではなく確定ラベルを保存する

この用途を許可する書面または契約条項を得た場合だけ、教師データ作成経路へ追加する。

## Qwenを第三者プロバイダー経由で使う場合

Qwen3.5-2Bの公開ウェイト自体はApache-2.0で、公式モデルカードもfine-tuningを想定用途としている。ただし、第三者の推論APIを使う場合はQwenのライセンスだけでなく、その推論事業者の利用規約も重ねて適用される。

「Qwenを提供している非公式プロバイダーなら教師データ作成に使える」とは限らない。確認時点では、Together AIとFireworks AIの標準規約にも、サービスを競合製品開発へ使うことを制限する条項がある。Outputを所有できる、またはZero Data Retentionを選べることと、Outputを別モデルの学習に利用できることは別問題。

OpenRouterも各モデル・推論プロバイダーの規約を利用者へフローダウンしており、OpenRouter経由にしても制限は消えない。

安全性の高い順:

1. Apache-2.0のQwen/PaddleウェイトをAWS等の汎用計算資源へ自分で配備する
2. 専用デプロイ型サービスで自分のモデルコンテナを動かし、契約上の学習利用可否を確認する
3. 推論API事業者から、出力を教師ラベルとして利用できる旨をメールまたは契約で得る
4. 標準規約が曖昧な共有推論APIを使う

第三者へ確認するときは、次の質問をそのまま送る。

> May we use outputs generated by your hosted Qwen model as candidate OCR labels, verify them against bibliographic records and by human review, and use the verified labels to train and commercially deploy our own 0.9B–2B task-specific book-spine OCR model?

書面でyesを得られない場合は学習データ生成に使わない。
